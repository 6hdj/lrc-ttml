# 示例输入

这两份是**同一首词**的两个版本，歌词是作者自撰的（随项目以 MIT 授权，可自由使用）。
没有歌词在手时，可以用它们立刻试一遍转换。

| 文件 | 说明 |
| --- | --- |
| [`sample.txt`](sample.txt) | 纯文本，只有行内容 |
| [`sample.lrc`](sample.lrc) | 带行级时间戳，**精度明显更高**（程序会按乐句切片识别） |

> ⚠️ 示例里没有音频文件（音频有版权，不便随仓库分发）。
> 要完整跑一遍，把 `--audio` 换成你自己的音频：
>
> ```bash
> python main.py --audio 你的歌.wav --lyrics examples/sample.txt -o out.ttml
> ```

## 这份示例刻意演示了哪些写法

### 1. 演唱者标记

```
[v1]
夜色落在窗台上
风把 旧信 翻了几行
```

* `[v1]` / `[v2]` 用来标**谁唱的**，会变成 `<p ttm:agent="v1">` / `v2`
  —— Apple Music 的左右分栏就靠这个。
* **标记是"粘性"的**：`[v2]` 之后的行会一直是 v2，直到遇到下一个标记。
  所以不用每行都标。
* 标记可以**单独占一行**，也可以**写在行首**（`[v1]夜色落在窗台上`），两种都认。
* 还支持这些写法：`[男声]` `[女声]` `[合唱]` `[旁白]` `[duet-a]` `[duet-b]` 等，
  完整对照表见 [README「多人演唱」](../README.md#多人演唱分声部--分人歌词)。

### 2. 背景和声

```
[v1]
（轻轻哼着）
走过了很远的地方
```

* **圆括号 = 背景人声**，会变成 `<span ttm:role="x-bg">`。
* 整行都是括号时，它会被**并进相邻的主唱行**，而不是单独成行 ——
  这不是实现偷懒，而是规范要求：AMLL 解析时 `x-bg` 不计入行文本，
  **背景人声单独成行 = 空行 = 播放器里看不见**。
* 也可以用 `[和声]` / `[bg]` / `[伴唱]` 标一整行。

### 3. 段落

空行 = 段落分隔，会变成 `<div>`（Apple 格式下带 `itunes:songPart`）。

### 4. 中英混行

示例里第 6 段是英文。用界面的「语言 → **自动检测**」（默认）即可，
**不需要手动切换语言** —— 写死「中文」会让英文段按中文解码、明显掉字。

## 自己写歌词时的几个提醒

* 文件编码：**UTF-8 最好**；中文 Windows 上的 GBK/GB18030 也能自动识别
  （见 [`textread.py`](../textread.py)）。
* 不要在歌词文件里写 `#` 注释 —— 工具会把它们当成歌词行。
  说明文字请写在单独的文件里（比如这份）。
* `.lrc` 里 `[v1]` 这类标记不占用时间戳位置，单独一行即可；
  但**不要**写成 `[00:12.00][v1]` 之外的怪形式，容易和元数据标签 `[ti:]` 混淆。
