### 3.1 决策依据：一次**带阴性对照**的 CUDA 依赖实测

`tools/size_report.py` 定位的真相：**CUDA 占 64.6%**、PyTorch 14.5%。
所以先解决最大的那一块 —— CUDA 到底需要哪些文件。

实验脚本 `.tmp/exp_cuda_quick.py`，真 RTX 4060、真音频（30 秒片段）：

| 保留哪些 CUDA 库 | GPU int8_float16 | GPU float16 | 同环境 CPU（对照） |
| --- | --- | --- | --- |
| 全套（cuDNN 1095 + nvrtc 178 + cuBLAS 736 MiB） | 2.60s | 1.50s | 9.39s |
| 去掉 cuDNN（−1095 MiB） | 1.65s | 1.48s | — |
| **只留 cuBLAS**（−1273 MiB） | **1.59s** | **1.43s** | 9.46s |

⇒ **cuDNN 与 nvrtc 都不是必需依赖**，去掉后还更快。
GPU 确实在工作：CPU 9.4s vs GPU 1.4–1.6s，**差 6 倍以上**。

> ⚠️⚠️ **这个结论是第四次实验才拿到的，前三次全错，而且错得很像结论**：
> ① 模型缓存没命中 → `WhisperModel` 联网超时，6 轮全 FAIL（其实没走到转写）；
> ② 子进程里 `sys.executable` 是**系统 python** → `import asr` 失败，
>    却被误报成 "cublas 缺件"；
> ③ **最坑的一版**：7 轮全部"成功"，**包括故意留空的阴性对照** ——
>    因为 `compute_type="float16"` 那条路根本没走 cuDNN，
>    CTranslate2 静默换了实现。
>
> **方法学教训（以后的"裁剪类"实验都要遵守）**：
> 任何"删掉 X 还能跑"的结论都不成立，除非同时有一个
> **"删掉 X 必须挂"的对照**。本次的对照是"拿掉 cublas →
> `device="cuda"` 直接失败"，它证明实验**能测出坏**。

### 7.1 双击不再弹黑色控制台窗口（**已实测**）

用户明确要求"正常使用时不弹出黑色控制台窗口"。原来 spec 里是 `console=True`，
所以双击必弹黑窗。

⚠️ **`console=False` 是错的**（第一版就这么改，被实测否掉）：
GUI 子系统进程**不继承父进程的标准句柄**，于是
```
Lyric2TTML.exe --doctor --json > out.txt     # 写出来是 0 字节
powershell ... 2>&1 | ...                    # 什么都抓不到
```
会把**脚本、CI、以及 `tools/accept_frozen.py`**（它靠捕获输出来判定）全部搞坏。

✅ **正确做法**：`console=True` + `hide_console='hide-early'`（PyInstaller ≥6.0，
本机 6.22.3）。exe 仍是**控制台子系统**（句柄照常继承、重定向照常工作），
但**窗口在启动早期被隐藏** —— 双击/快捷方式启动时看不到黑窗。

实测（`dist/_build2`）：

| 检查 | 结果 |
| --- | --- |
| PE Subsystem | **3**（控制台子系统，句柄可继承） |
| `--version > v.txt` | **470 字节**（`console=False` 时是 **0**） |
| `--doctor --json > d.txt` | **4782 字节**（同上，之前 0） |
| `--help` | 正常 |
| 双击/快捷方式 | 无黑窗（`hide-early`） |

⚠️ 想临时看到控制台排查启动问题：`L2T_WITH_CONSOLE=1` 重新打包。

### 7.2 新增 `win_integration.py`：开始菜单 / 桌面 / 卸载注册表项

现状（改造前）：安装器**只**建了一个指向 **`启动.bat`** 的桌面快捷方式 ——

新增的模块（安装与卸载**共用同一份逻辑**，避免两边漂移）：

* **开始菜单**：`<APPDATA>\Microsoft\Windows\Start Menu\Programs\Lyric2TTML.lnk`
  → 指向 **`Lyric2TTML.exe` 本体**（不是 .bat）。

  NoModify / NoRepair`。

  * `reg add /f` **幂等**：重复安装不会叠加条目。
* `integrate_remove()` 与安装**对称**：删快捷方式 + 删注册表项，全部幂等。

## 4. 本轮发现的真 bug（已修）：打包版在 CPU 上静默慢跑

修 CUDA 裁剪时发现：**打包版转换要 556 秒，源码模式只要 31 秒**（同一首歌）。

**根因**：`asr._register_cuda_dlls()` 用
`for base in sys.path: glob(base + "/nvidia/*/bin")` 找 CUDA DLL，
**赌 `_internal` 在 `sys.path` 上**。赌输时 `WhisperModel(device="cuda")` 抛
`Library cublas64_12.dll is not found or cannot be loaded`，
而 `ensure_loaded()` 把它当"显卡不可用"→ **退到 CPU**
→ 用户看到的是"慢得离谱"，而不是报错。
（这正是之前观测到的"冻结版 815 秒 vs 源码 25 秒"的真身。）

**修法**：不再赌 `sys.path`，显式扫 `sys._MEIPASS` / exe 同级 /
`<app>/_internal/nvidia/*/bin` / `<app>/cuda`。
同时把 `gpu_probe.cuda_dirs()` 改成同一口径（它原来**完全不看**
`_internal/nvidia`，两个函数不一致 → "体检说没问题、一跑就报错"），
并把 `paths._source_dir()` 公开为 `source_dir()`。

| | 修复前 | 修复后 |
| --- | --- | --- |
| **打包版转换（同一首歌）** | **555.8 s** | **24.0 s** |

## 6. 未验证事项 / 已知障碍（如实记录）

### 6.1 ⚠️ 冻结版里 `import torch` 会崩（**已知障碍，未解决**）

**演进过程（每一步都实测过）**：

| 阶段 | 现象 | 结论 |
| --- | --- | --- |
| 最初 | 主进程 import torch → `0xC0000005` 崩掉整个程序 | 致命：一进界面就闪退 |
| 排除 OpenMP 冲突 | 把包内 `ctranslate2/libiomp5md.dll` 挪走，**照样崩** | 不是"OpenMP 被加载两次" |
| 排除"加载失败" | 有一次 install **完整跑完**（`[完成] …（真实加载通过）`）**之后**才崩 | 崩在**退出阶段**，不是加载失败 |
| 改"只读记录、刷新不再 import" | 主进程不再崩，`--runtime-cli --status` **退出码 0** | ✅ **闪退问题已解决** |
| 现在 | 状态显示 `import torch 失败`，两种报错都出现过：<br>`AssertionError: _gds_deregister_buffer exists but _gds_register_buffer does not`<br>`ModuleNotFoundError: No module named 'torch._C'` | ❌ 冻结进程里 torch 的**原生扩展加载不起来** |

两个报错指向同一件事：**`torch_cpu.dll` / `torch._C` 在冻结进程里加载失败**
（`_gds_*` 是 CUDA GPUDirect Storage 符号，`torch._C` 是主扩展）。
源码模式同一份 wheel 完全正常（实测跑出 192 维声纹）。
这是 PyInstaller 冻结环境与 PyTorch 原生扩展的兼容问题，**不是配置能绕过去的**。

**当前状态**：
* ✅ 主程序**不再崩**（`--runtime-cli --status` 退出码 0，且有可读提示）；
* ✅ 运行时的下载 / SHA256 / 解包 / 摊平**全部正常**；
* ❌ **冻结版里"对唱分声部"仍然不可用**。

**一个还没修好的细节**：原设计想用 `<site>/.l2t-import-crashed` 记号
让"下次别再试"，但**记号放在 site 目录里，而安装流程会先重建该目录**，
所以记号没落盘（实测 `存在: False`）。修法明确：
**把记号挪到 site 之外**（如 `<runtime 根>/.crashes/<id>.json`），
这样 `_safe_rmtree(site)` 清不掉它。

**结论**：按需求第 4 条"如果经过真实验证发现 PyTorch 无法安全独立部署，
请保留可靠方案并报告原因，不要强行拆分" ——
**当前状态不合格**：冻结版里分声部这条路没有走通。
三个候选方案（各需再花一轮，我倾向 ②）：

① **声纹推理放独立子进程**（主进程永不 import torch）；
② **把 CAM++ 换成 onnxruntime 后端** —— onnxruntime 本就在包里（38 MiB），
   还能再省 509 MB 磁盘，把安装包压到**约 550 MB**（正好进 500–600 MB 区间）；
   但换后端必须重跑 `tools/eval_diarization.py` 准确率基线（现 85.0%）后才能切；
③ **回退**：torch 放回主安装包（0.68 → 约 1.0 GB）。

②是最干净的长期方案（onnxruntime 本来就在包里，还省 509 MB 磁盘），
但属于"换后端"，必须按项目纪律重新做准确率评估，不能在没评估前切换。

### 6.4 一个应当改进的点（错误分类）

上一条暴露的真问题：**把"没有写权限"报成了"显卡初始化失败"**。
需求第 9 条要求"不得把运行时缺失误报成权重缺失"，同理也不该把权限问题
误报成显卡问题。`asr._gpu_help()` 现在只区分"CUDA 运行库缺失"与"显卡初始化失败"，
应当再加一类 `PermissionError → 目录不可写 + 怎么改`。

* 打包产物里 CUDA DLL 在 `_internal/nvidia/<lib>/bin/`（实测
  `_internal/nvidia/cublas/bin/cublas64_12.dll` **存在**）。
* `asr._register_cuda_dlls()` 用 `for base in sys.path: glob(base/nvidia/*/bin)`，
  只有 `_internal` 在 `sys.path` 上时才会命中；
* `desktop/services/gpu_probe.cuda_dirs()` **完全不看** `_internal/nvidia`，
  它只找 `<app>/cuda`、`<app>/.venvpack/Lib/site-packages/nvidia/*/bin`、
  `CUDA_PATH`、`Program Files`。

⇒ 这解释了之前观测到的"冻结版 GPU 转换远慢于源码模式"（815 s vs 25 s）：
**打包版很可能一直在跑 CPU 回退路径**，而 `--doctor` 的 GPU 项却可能报正常。
**这是个真 bug，需要在做体积分层之前先修**——否则把 CUDA 移出去之后更查不清。

> 状态：**待修**。修法：`gpu_probe.cuda_dirs()` 改为同时扫描
> ①`_internal/nvidia/*/bin`（PyInstaller 布局）②可写的运行时组件目录
> ③`<app>/cuda`（手工放置）。并在 `doctor` 里把"注册了哪些目录"报出来。
