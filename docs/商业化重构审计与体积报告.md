## 2. 本轮已完成的裁剪（阶段 B 第一批）

`Lyric2TTML.spec` 新增**显式 prune**（可 `L2T_NO_PRUNE=1` 关掉对照），只删
"能说清为什么不需要"的东西，**绝不删 .dll/.pyd**：

| 裁掉的东西 | 依据 |
| --- | --- |
| `models/`（293 MiB → 65 KiB） | 需求原文要求模型权重不进安装包。其中 `singer_identity/**` 5×37MiB 是**已冻结、被否决的实验**（`singer_ssl.py`，自检第 24 组禁止生产引用），`demucs` 权重 80MiB、`campplus` 权重 27MiB 都由模型管理器按需下载；**只保留 `campplus_src/` 网络定义**（缺了会让「强制双声部」静默退回单人） |
| `torch/include`（38 MiB）、`torch/lib/*.lib`（42 MiB）、`torch/bin/protoc.exe` | 编译期产物与命令行工具，运行时不需要 |

## 3. 下一步：CUDA / PyTorch 分层（决定能否到 500–600 MB）

### 3.1 现状分析

`cublas + cudnn + nvrtc` 只服务一件事：**CTranslate2 的 CUDA 推理**（Whisper）。
`torch` 只服务一件事：**CAM++ 声纹**（`speaker_campplus.py`）。

两者都**可以**从主安装包移出去，做成"首次启动按需下载的运行时组件"
（需求原文 §七-B 明确允许："将部分可独立部署的 GPU 运行组件作为独立运行时组件，
在安装或首次启动时按需安装"）。

### 3.2 关键发现（本轮实测，会影响方案）

**冻结版的 CUDA DLL 目录注册不完整。**

* 打包产物里 CUDA DLL 在 `_internal/nvidia/<lib>/bin/`（实测
  `_internal/nvidia/cublas/bin/cublas64_12.dll` **存在**）。
* `asr._register_cuda_dlls()` 用 `for base in sys.path: glob(base/nvidia/*/bin)`，
  只有 `_internal` 在 `sys.path` 上时才会命中；
* `desktop/services/gpu_probe.cuda_dirs()` **完全不看** `_internal/nvidia`，
  它只找 `<app>/cuda`、`<app>/.venvpack/Lib/site-packages/nvidia/*/bin`、
  `CUDA_PATH`、`Program Files`。

⇒ 这解释了之前观测到的"冻结版 GPU 转换远慢于源码模式"（815 s vs 25 s）：
**打包版很可能一直在跑 CPU 回退路径**，而 `--doctor` 的 GPU 项却可能报正常。
**这是个真 bug，需要在做体积分层之前先修**——否则把 CUDA 移出去之后更查不清。

> 状态：**待修**。修法：`gpu_probe.cuda_dirs()` 改为同时扫描
> ①`_internal/nvidia/*/bin`（PyInstaller 布局）②可写的运行时组件目录
> ③`<app>/cuda`（手工放置）。并在 `doctor` 里把"注册了哪些目录"报出来。

### 3.3 候选方案

| 方案 | 估算主包 | 首启还需下载 | 说明 |
| --- | --- | --- | --- |
| A 现状（全带） | 1.82 GB | 模型 3 GB | 已经太大 |
| B 全带 + 上述裁剪 | ~1.5–1.6 GB | 模型 3 GB | 零碎裁剪的上限 |
| C 移出 PyTorch（CAM++ 变可选） | ~1.45 GB | torch 400 MB + 模型 | 只省 14% |
| **D CUDA+torch 都做成运行时组件** | **~150–250 MB** | GPU 运行时 ~1 GB + 模型 3 GB | 唯一能到 500 MB 附近的方案；分声部/GPU 识别在下载后可用 |
| E D + 把模型也首次启动下载 | 同上 | 同上 | 与 D 相同（模型本来就不打包） |

**推荐 D**：主安装包变成"能装、能开、能引导"，重活按需下载且可校验可续传。
代价是首次使用总下载量更大（约 4 GB），这必须**如实告诉用户**，不能假装是纯体积优化。

⚠️ 需要先确认的事实（未验证）：
* ctranslate2 是否**必须** `cudnn` 全套，还是只需要 `cublas + cudnn_ops/cnn`；
  `cudnn_engines_precompiled64_9.dll`（504 MiB）去掉后是走 JIT 还是直接失败。
  这一条能省 500 MB 以上，值得专门做实验（前面三次实验都因脚手架问题没得出结论）。
* wheel 方式的 CUDA 包能否覆盖 ctranslate2 需要的全部 DLL。
