## 一、阶段一：工程审查（完成）

### 前端技术栈

| 项 | 事实 |
| --- | --- |
| GUI 框架 | **PySide6 (Qt 6)**，非 Web |
| 页面入口 | `desktop/app.py` → `desktop/main_window.py` → `desktop/pages/*` |
| 页面清单 | `welcome`(开始) / `home`(歌词工作台) / `tasks`(任务中心) / `models`(模型管理) / `settings`(设置) / `help`(帮助·诊断) |

| 状态 | `AppContext`（context.py）持有全部服务单例；界面**只能**通过它调服务 |
| 后端通信 | 进程内直接调服务层（`desktop/services/*`），**不是 HTTP**；编辑台另走本地 HTTP |

| 打包 | PyInstaller onedir；`launcher.py` 是入口；`--uicheck/--selftest/--launch-check` 等开关 |

## 五、阶段五：交互细节（部分完成）

### 已完成

* **Ctrl+1..6 切页**（对应六个导航项）；
* **Esc**：当前页有可取消任务 → 取消；否则退回「开始」页。
  语义是"退回/取消"，**不是退出软件**（退出仍走关闭按钮 + 确认框）；
* **Enter**：触发当前页 `submit_current()`。用
  `WidgetWithChildrenShortcut` 上下文，避免与聚焦按钮重复触发；
* 新增 `empty_state()` 统一空状态组件（备用）。

### Enter 的"接与不接"是有判据的（写进 `Page` 基类契约）

Enter 只接**"确认/提交表单"**这一类动作，**不接"启动昂贵后台任务"**：

| 页面 | 接 Enter？ | 理由 |
| --- | --- | --- |
| `home` | ✅ 开始制作 | 页面本身就是"填完表单提交" |
| `settings` | ✅ 保存 | 幂等、廉价、符合 Enter 语义 |
| `welcome` | ❌ | 主按钮是"下载 3 GB 模型 / 529 MB 运行时"，误触代价高 |
| `models` | ❌ | 同上（下载必须靠明确点击） |
| `tasks` / `help` | ❌ | 没有"主操作"语义 |

这条判据被测试守着（`tools/test_design_consistency.py` 第 6 组）——
以后新增页面会被提醒先想清楚，而不是随手接上。

### 用"断言"代替"看图"（我没法逐屏人工核对）

任务书要求"逐屏人工视觉核对"，但我**不具备看图能力**（只能读像素值）。
更重要的是：**就算能看，人眼也查不出**"第 3 页卡片圆角 8px、第 5 页 10px"
这种系统性问题 —— 而那正是任务书说的"页面拼接感"。

所以新增 `tools/test_design_consistency.py`（已接进交付报告），
把"一致性"变成可执行断言：

1. 两套主题 QSS **无残留占位符**，且 `:pressed`/`:focus`/`:disabled` 齐全；
2. **页面里不许出现** `font-size:` / `border-radius:` 字面量（漂移即失败）；
3. **所有卡片内边距同源**（实测 `(16,14,16,14)` 一种，来自 token）；
4. 两套主题**键集相同**；
5. **两种主题下六个页面都能渲染**出非零尺寸；
6. **页面构建失败必须算失败** —— 否则"内边距只有一种"会因为
   "页面压根没建出来"而**空过**（假绿）；
7. Enter 挂钩符合上面的契约。

**变异验证**（`.tmp/mutate_design.py`）：两个变异都必须被抓住 ——
① 往 `models.py` 塞一处 `font-size: 17px` → **抓到**；
② 给 `help.py` 一个卡片传 `margins=(4,4,4,4)` → **抓到**
（`发现 2 种: [(16,14,16,14), (4,4,4,4)]`）。

⚠️ 顺带记一条：变异②的第一版把关键字参数插在位置参数**之前** →
SyntaxError → 页面编译不过 → 检查**空过**（假绿）。
这既说明"变异本身也要写对"，也直接催生了上面第 6 条防护。


### 未完成 / 判定已达标

### 过程中抓到的真 bug（本轮最有价值的产出）

**⓪【致命】真实运行时页面从来没被构建 —— v1.1.0 起所有发布版内容区都是空白**

用户报的症状：**侧边栏在、页面标题在，内容区一片空白（卡片没了）**。
我前面查过好几轮都没复现（源码模式、冻结版 `--uicheck`、125% DPI、
用户窗口尺寸 1393×982），**因为那些检查都不走真实路径**。

根因：页面是**懒构建**的（`_page()` 只造实例，`build()` 由 `ensure_built()` 调），
而 `show_page()` 原来只调 `on_show()` → `refresh()`，`refresh()` 开头是
`if not self._built: return` ⇒ 第一次进任何页面都是空的；而
**没有任何生产代码路径**会再调 `ensure_built()`（`app.py` 只建 `MainWindow()`）。

`git log -S "ensure_built"` 全历史：只出现在 `pages/base.py`（定义）与
`uicheck.py`（自检）—— **v1.1.0 的 `445ef31` 起就是这样**，
**两个发布版的内容区都是空的**。用户看到的"页面标题"其实是底部状态栏里的
`page.TITLE`。

**为什么自检 14/15 项全过却漏了它（本仓最典型的假绿）**：
`uicheck.py` 里**自己**调了 `page.ensure_built()` —— 它测的是
"页面**能**构建"，而不是"真实运行时会构建"。差的就是这一步，而它决定产品能不能用。

修法：`show_page()` 里**先 `ensure_built()` 再 `on_show()`**。
新增守卫：`uicheck` 加 **「真实路径（只调 show_page，不手动构建）」** 专项，
变异验证通过（去掉修复 → 立刻报 `_built=False`）。

**① `closeEvent` 在无头模式下永久阻塞**

写"窗口缩放"校验时脚本卡在 `w.close()` 十几分钟。原因：
`MainWindow.closeEvent` 里只要还有任务在跑就**直接调 `QMessageBox.question`**，
而无头场景（界面自检/CI/验收脚本）只有 `processEvents()`、没有 `app.exec()`，
模态框没人能关 → 永久阻塞。

这违反了项目**自己写在 `Page.say/ask` 注释里的约定**
（"所有弹窗走 `Page.say()/ask()`，识别 `L2T_HEADLESS=1` 时改成打印"）。
修法：无头时打印一行 + `event.ignore()`（按"不关"处理，保守方向正确 ——
自动化里误关会真中断任务）。修完 resize 测试从"卡死"变成 **4/4 通过**。

**② `archives` 多条目被当成"都要下" —— 用户多下一倍（1 GB 而非 529 MB）**

冻结验收日志里写着「需要下载 **1.0GB**」，而 cuda 实际只需 528.8 MB。
这是我在 Phase 4 加国内镜像时引入的：把镜像写成**第二个 archives 条目**，
但下载循环 `for w in items` 会**逐个都下** —— "备选源"变成"两个都下"
（zip 528.8 + wheel 527.5 = 1056.3 MB）。

**这个 bug 一共修了三次才收敛**，因为同一个语义散在**三处**：

| # | 位置 | 症状 |
| --- | --- | --- |
| ① | `download()` 进度总量 | 日志显示 1.0GB |
| ② | `download()` 成功即止 | 真去下第二个源（含**缓存命中**那条路径，也漏了） |
| ③ | `_check_uncached()` 的 `download_bytes` | **界面「模型」页仍显示 1.0GB** |

最终**抽出唯一实现**（`_entries_of` / `_is_alternatives` / `_download_bytes`），
让语义只有一处定义。修完后验收日志变成 `需要下载 528.8MB`、
runtime install 从 **1113s → 3.7s**。

**教训**：一个语义如果在多处各写一遍，修 bug 必须**每处都过一遍**，
而且最好**先抽成唯一实现再修**。

**③【视觉】主按钮「开始制作」看不见（白底白字）**

`main_window.py` 上有 `self.stack.setStyleSheet("background: transparent;")`。
Qt 的规则是**控件级样式表对该控件及其子树优先级高于应用级样式表** ——
于是页面里**所有按钮底色被强制透明**：主按钮只剩白字画在浅灰页面上，
整条「开始制作」看不见。**任何属性断言都测不出来，只有看截图才看得见。**
（`tools/test_design_consistency.py` 现在用**运行时遍历控件树**守着：
凡"有非空 styleSheet 且还有子控件"的容器一律报错。静态扫源码的版本
我写过一版，**变异验证没抓到** —— 因为那行是 `self.stack.…`，
变量名看不出类型。）

**④【视觉】卡片里一条条灰色横带**

`QWidget { background: {{bg}} }` 是**通配**规则，会命中 `row()`/`col()` 造的
匿名容器 → 白卡片内部出现灰横带（输入行、按钮行、提示行全被"贴"了灰底），
界面看着像拼出来的。改成**容器默认透明**，只由 窗口/页面栈/侧边栏/卡片 负责画底。

**⑤【视觉】页面标题与导航名不一致**

导航「歌词工作台」的页面写着「制作逐字歌词」；「任务中心」写「任务」、
「模型管理」写「模型」。统一为**标题 = 导航名**（欢迎页豁免：标题是问候语）。

**⑥ 两处测试基础设施误报**（不是产品问题，但会假装产品坏了）

* `desktop/selftest.py` 第 14 组：本机 `urllib.getproxies()` 返回
  `http=http://127.0.0.1:65532`（注册表里的本地代理），
  于是 `urlopen("http://127.0.0.1:…")` **被发给代理** → `WinError 10061`。
  误导性极强：**原始 socket 连同一端口完全正常**，只有 urllib 失败。
* 随机端口 `("127.0.0.1", 0)` 在本机"绑得上但连不上" → 改成逐个候选端口真连一次再选。

### 「看截图」这件事本身（方法论）

我一开始以为**自己看不了图**，于是写了 `test_design_consistency` 当替代品。
后来发现 `read_image` 是可用的 —— **能看图之后，一轮就抓出上面 ③④⑤ 三个真 bug**，
每一个都是"属性断言永远测不到、用户一眼就看到"的那类。

于是把这件工作固化成工具：**`tools/shot_pages.py`** 一键生成
**6 页 × 2 主题**共 12 张快照到 `docs/ui-shots/`，别人打开目录就能一次看完。

⚠️ 它还踩了一个坑值得记：**必须用 `windows` 平台插件，不能用 `offscreen`**。
`offscreen` 下 Qt 看不到系统字体库（只有 2 个字族），`▾` 会画成**豆腐块** ——
我一度以为产品缺字形，用真平台验证后是**正常倒三角**（首行宽 22 → 末行宽 1）。
**看图的工具必须走和用户一样的渲染路径，否则看到的不是产品。**
现在脚本会打印渲染平台与字族数，字族过少时给出警告。
