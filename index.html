提示：歌词文本要与音频版本一致；中文请用 UTF-8 编码。 支持 [v1] [v2]、[duet-a] [duet-b]、[narration]/[旁白] 演唱者标记，以及 （括号）背景和声。

⚙️ 转换参数

交给 whisper 自己判语言（language=None）。 中英混唱不用手动切 —— 写死「中文」会让英文段按中文解码、明显掉字；
只有确定整首都是同一语言、或自动检测判错时，才手动指定。 xml:lang 会自动写成实际检测到的语言。
TIFA 是歌声音素对齐引擎，实测逐字比 Whisper 更准；
需要逐句 LRC 和 models/tifa，缺失或失败会自动回退 Whisper。
本项目强制用 GPU —— 用 CPU 处理一首歌要几分钟， 所以没有做 CPU 降级。没有可用的显卡时会直接明确报错， 而不是悄悄变慢。
选「星号屏蔽」时，命中词表的脏话会整个换成 ****。
（以前这里还有一个「检测被消音的词也用 **** 替换」开关 —— 它和这一项 最终效果完全一样，两个控件放在一起只会让人不知道该开哪个， 已移除。需要那条启发式的脚本可以继续用命令行 --detect-muted。）
先用 Demucs 分离人声再识别（混音复杂/和声多的歌更准，首次要下 80MB 模型）
按乐句切片识别（更准，稍慢）
低匹配率行二次精修
自动跳过「作词/作曲」等制作人员行
允许同歌手拖音跨行重叠（实验：拖音更长；部分工具/商店可能不接受；需开启人声分离）
分层歌词（允许主歌词/和声/附加句在时间上同时出现；不再压缩同一声部重叠）
⚠️ 音频判不出到底几个人（三种判据实测全部失败），所以人数由你来定， 这里不再假装「自动判断」。
关闭：不跑声纹，直接用歌词里的 [v1] [v2] 标记，没标记就全 v1；
强制 N 声部：用原始混音提声纹 + k-means 聚成 N 簇， 与 AMLL 官方人工标注实测 90.6% 一致；会覆盖歌词标记（想按标记分就选「关闭」）。
分完会在日志里列出把握不足的行，去编辑台改几行即可。 两人同时张嘴的齐唱/和声无法拆分。
设为 0.5 时，字与字之间停顿超过 0.5 秒会在前一个字后加一个空格（AMLL 用空格表示停顿）。

🎵 歌曲信息（可选，写进 TTML 元数据）

⚠️ AMLL 官方只定义了 4 个平台键（网易云 / QQ / Apple / Spotify）； 酷我、酷狗是我们扩展的自定义键（kuwoMusicId / kugouMusicId）。我们的写器会原样保留，AMLL 解析器会忽略不认识的键 —— 也就是能存下来、不会让歌词显示不出来，但别的软件不认。
为什么不做"自动检索并回填"：① 本项目的卖点是离线、无需 API Key， 接第三方检索就把这条打破了；② 更麻烦的是检索会搜错歌—— 同名/翻唱/现场版遍地都是，填错的 ID 比空着更糟（指向另一首歌）。 所以这里只做"一键到平台搜索页"，把选哪一首这一步留给你。
真要自动回填：Meting-Agent（自建服务，统一 search 接口， 覆盖网易云/腾讯/酷狗/酷我）可以接 —— 设环境变量 L2T_METING_API 指向你的实例即可启用（见 README）。

💡 它是怎么工作的

1. 用 faster-whisper large-v3 听音频，拿到真实的词级时间戳；
2. 把歌词按字切分，用动态规划强制对齐钉到识别结果上（同音字、漏字、复读都能容错）；
3. LRC 行级时间戳作为锚点约束每一行；
4. 匹配率低的行会单独重听那一小段再对齐；
5. 输出 AMLL / Apple 格式 TTML 并做确定性自检。
全程本地运行，不上传任何数据到云端。
